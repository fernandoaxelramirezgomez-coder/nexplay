\subsection{De los datos a la interfaz}\label{sec:arquitectura-flujo}

La figura~\ref{fig:arquitectura} sigue el camino de los datos. La ingesta bajó las reseñas y las
fichas de Steam y las publicó en releases con tag fijo (sección~\ref{sec:datos-releases}). De ahí
en adelante nada vuelve a consultar Steam: el build de la API y los notebooks bajan esos releases
y comprueban su sha256. El frontend es un sitio estático que consulta a la API. Todo el Python
vive en \texttt{backend/} y el frontend en \texttt{frontend/}; la estructura completa y el tag
del código están en el anexo~\ref{sec:anexo}.

\subsection{Verificaciones en el build}\label{sec:arquitectura-build}

Render construye la API con \texttt{backend/despliegue/Dockerfile}, y el build falla si algo no
cuadra. \texttt{preparar\_entorno.py} baja data-v3, que es lo que se sirve, y data-v1, con la que
se entrena, y se detiene si el sha256 de alguna no es el publicado. Luego entrena el modelo con
data-v1 y la partición congelada, y \texttt{verificar\_bandas.py} califica los
\cifraJuegosCatalogo{} juegos y compara cada banda con la referencia validada: si cambia una sola,
el build falla; el generador de este documento repite esa comparación
(sección~\ref{sec:evaluacion-filo}). Por último, el build rechaza la imagen si le llega una
biblioteca de modelos de texto, que deben calcularse fuera de la API.

\subsection{Endpoints}\label{sec:arquitectura-endpoints}

La API expone \cifraEndpoints{} endpoints (tabla~\ref{tab:endpoints}), descritos en su página
\texttt{/docs}\footnote{FastAPI arma esa página con el contrato OpenAPI de cada endpoint: qué
recibe, qué devuelve y qué errores da.}. Todo lo que entra se valida con Pydantic\footnote{Una
biblioteca de Python que revisa el tipo y el rango de cada dato de entrada y rechaza la
solicitud si no cumple.} antes de tocar el modelo o la base. \texttt{/prediccion} sigue
recibiendo el perfil por compatibilidad, pero el riesgo que devuelve es del título y no cambia
con él (sección~\ref{sec:modelacion-bmas}).

\subsection{Costos y límites}\label{sec:arquitectura-limites}

La API está en el plan gratis de Render: se duerme cuando nadie la usa, y la primera consulta
después tarda en responder. Su disco es efímero, así que las calificaciones, los comentarios y los
votos a Nia (\texttt{valoraciones.db}) se borran al reiniciarse; el catálogo y el modelo vienen
dentro de la imagen y no se pierden. Nia usa un modelo de lenguaje de OpenAI solo si el servidor
tiene clave y modelo; si no, contesta por reglas, sin costo. Los comentarios, las reacciones y las
consultas y votos a Nia tienen un límite por minuto, por usuario y por IP, que acota el abuso y el
gasto.
